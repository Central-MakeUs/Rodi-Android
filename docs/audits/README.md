# docs/audits — 시점별 코드 조사 스냅샷

## 이 폴더의 규칙

**여기 있는 문서는 현재 사실이 아니다.** 특정 시점·특정 커밋에서 코드베이스가 어땠는지를
기록한 것이다. **조사 수치의 원본**은 여기에만 둔다.

`../BACKLOG.md`에도 수치가 나올 수 있다 — 단 **커밋과 재검증 명령이 함께 붙은 요약**일 때만이고,
원본은 여전히 이 폴더다. 규범 문서(`../conventions/`, 전역 스킬)에는 카운트를 두지 않는다.

- **갱신하지 않는다.** 오래됐다고 고치지 말 것. 다시 조사할 일이 생기면 **새 날짜로 새 파일**을
  만든다. 옛 스냅샷은 역사로 남는다.
- 각 문서 머리에 **조사일·커밋 SHA·범위·제외 대상·도구 버전**이 있어야 한다.
- 각 수치에 **그 수치를 만든 명령**이 붙어야 한다.
- **"지금 몇 개야?"라는 질문에 이 숫자를 답하지 않는다.** 리포에서 재측정한다.

## 언제 새 Audit을 만드나

주기적으로 돌리지 않는다. 다음 중 하나가 있을 때 만든다.

- 대규모 리팩터 / 아키텍처 변경 뒤
- 이 프로젝트의 컨벤션을 다른 프로젝트로 옮기려 할 때
- 에이전트가 기존 규칙과 반복적으로 충돌할 때
- 오래된 조사 결과를 중요한 결정 근거로 다시 써야 할 때

**stale 문서를 계속 유지보수하는 것보다, 오래된 스냅샷을 역사로 남기고 필요할 때 다시
조사하는 쪽이 1인 개발자에게 싸다.**

## 어떻게 만드나

조사 프롬프트는 전역 스킬에 있다 —
`~/.claude/skills/android-code-standard/references/codebase-audit-prompt.md`.
`<REPO>`/`<PACKAGE>`를 채워 구현 에이전트에 넘기면 세 덩어리로 산출된다.

| 산출물 | 어디로 |
|---|---|
| 관찰·수치 | 이 폴더에 `<날짜>-<주제>.md` |
| 유지할 규칙 | `../conventions/` (카운트 빼고, 재검증 명령만) |
| 불일치·수정 대상 | `../BACKLOG.md` |

**섞어서 한 파일에 두지 않는다.** 수명이 다른 것들이 묶이면 같이 썩는다.
