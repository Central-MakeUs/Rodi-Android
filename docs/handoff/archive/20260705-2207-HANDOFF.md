## Context (왜)
Rodi는 지도 앱 특성상 콜드 스타트 비용이 크다(`RodiApplication.onCreate()`에서 `KakaoMapSdk.init` +
`KakaoSdk.init` 동기 초기화, 이후 Compose 초기 컴포지션). 목표는 Baseline Profile을 도입해
DEX 인터프리터 실행 구간을 줄이고 콜드 스타트(첫 프레임까지)를 단축하는 것. (참고:
[docs/PROJECT.md](../PROJECT.md), 로드맵 메모상 "계획 도입" 항목이었으나 우선 착수)

## Spec (무엇을·어떻게)
Android 공식 Baseline Profile 워크플로(AGP `androidx.baselineprofile` 플러그인 + Macrobenchmark)를
그대로 따른다. 수동으로 `baseline-prof.txt`를 작성하지 말고, 반드시 플러그인이 자동 생성/삽입하도록 구성한다.

1. **버전 카탈로그(`gradle/libs.versions.toml`)에 추가**
   - `androidx.benchmark:benchmark-macro-junit4` (최신 stable)
   - `androidx.test.uiautomator:uiautomator` (최신 stable)
   - `androidx.profileinstaller:profileinstaller` (최신 stable)
   - Gradle 플러그인 `androidx.baselineprofile` (com.android.tools.build 계열, 최신 stable —
     AGP 9.2.1과 호환되는 버전으로 고정)
   - 정확한 버전 넘버는 직접 확인 후 pin할 것(`/version_control_wisdom` 스킬 참고). 기존 네이밍
     컨벤션(`androidx-*`, camelCase 버전 키)을 그대로 따를 것.

2. **신규 모듈 `:benchmark` 생성** (`com.android.test` 플러그인, `:app`을 타겟)
   - `settings.gradle.kts`에 `include(":benchmark")` 추가.
   - `benchmark/build.gradle.kts`: `targetProjectPath = ":app"`, `minSdk = 30`(app과 동일),
     `experimentalProperties["android.experimental.self-instrumenting"] = true`.
   - `benchmark/src/main/AndroidManifest.xml`: 최소 매니페스트(패키지만).
   - `benchmark/src/main/java/com/dororong/rodi/benchmark/BaselineProfileGenerator.kt`:
     `BaselineProfileRule`로 `pressHome()` → `startActivityAndWait()`만 수행하는 최소 시나리오.
     (로그인/약관 게이트를 넘어 홈 화면·지도까지 자동화하는 것은 Out of scope — 아래 참고)
   - `benchmark/src/main/java/com/dororong/rodi/benchmark/StartupBenchmark.kt`:
     `MacrobenchmarkRule` + `StartupTimingMetric()`으로 `CompilationMode.None()`과
     `CompilationMode.Partial(BaselineProfileMode.Require)` 두 케이스를 비교 측정하는 테스트.

3. **`:app` 모듈 수정**
   - `alias(libs.plugins.androidx.baselineprofile)` 플러그인 적용.
   - `dependencies { baselineProfile(project(":benchmark")) }` 추가.
   - `implementation(libs.androidx.profileinstaller)` 추가.
   - `buildTypes`에 `benchmark` 빌드 타입 추가: `initWith(release)`,
     `signingConfig = signingConfigs.getByName("debug")`(현재 release 서명 설정이 없어 로컬
     벤치마크 설치를 위해 debug 서명 사용), `matchingFallbacks += listOf("release")`,
     `isDebuggable = false`. 기존 `release` 블록(minify/shrinkResources/proguard) 설정은 건드리지 않는다.
   - `baselineProfile { }` 블록은 플러그인 기본값(자동 관리 방식, `automaticGenerationDuringBuild`는
     기본 `false` 유지 — CI 미연동이므로 수동 생성)으로 둔다.

4. **생성 확인**
   - Android Studio "Generate Baseline Profile" 실행 또는 해당 Gradle task로 `baseline-prof.txt`를
     생성하고, `app/src/main/generated/baselineProfiles/`(플러그인이 실제로 쓰는 경로 기준) 아래
     파일이 생기는지 확인. 이 생성 파일은 커밋 대상(플러그인이 산출물로 관리).

## Acceptance criteria
- [ ] `:benchmark` 모듈이 신설되고 `:app`을 타겟팅하며, 기존 모듈 빌드에 영향 없음
      (`./gradlew assembleDebug` 정상 동작).
- [ ] 연결된 실기기/에뮬레이터(API 28+)에서 Baseline Profile 생성 태스크 실행 시
      `baseline-prof.txt`가 생성되고, 그 안에 `com/dororong/rodi/` 관련 클래스(Application,
      MainActivity, Hilt 생성 코드 등)가 포함되어 있음(육안/grep 확인).
- [ ] `StartupBenchmark` 테스트가 `CompilationMode.None()` vs
      `CompilationMode.Partial(BaselineProfileMode.Require)` 두 케이스의 콜드 스타트 시간을
      측정 리포트(Android Studio 자동 생성 JSON/HTML)로 남김 — profile 적용 케이스가 더 빠르거나
      최소한 유의미하게 느려지지 않음.
- [ ] `app` release 빌드(`assembleRelease`)가 기존과 동일하게 동작(minify/shrinkResources 유지).
- [ ] 기존 유닛 테스트(`./gradlew test`) 회귀 없음.

## Verification
```
./gradlew :app:assembleDebug
./gradlew :app:assembleRelease
./gradlew test
# 아래는 실기기/에뮬레이터 연결 필요 (정확한 task 이름은 플러그인 버전에 따라 다를 수 있음 —
# Android Studio "Generate Baseline Profile" 실행 결과 로그에서 실제 실행된 task 이름 확인)
./gradlew :benchmark:connectedBenchmarkAndroidTest
```

## Out of scope
- 로그인/약관 게이트를 넘어 홈 화면·지도 렌더링까지 포함하는 "critical user journey" 벤치마크
  (Instrumentation으로 카카오 로그인을 자동화해야 해서 별도 작업 필요).
- CI에서 벤치마크 자동 실행(`automaticGenerationDuringBuild` 등) — 우선 로컬/수동 실행만.
- Startup Profile(Dex layout 최적화), Baseline Profile 외 추가 최적화(App Startup 라이브러리 도입 등).
- 릴리스 서명 설정 자체를 새로 만드는 것 — 이번엔 `benchmark` 빌드 타입에서 debug 서명을
  임시로 재사용하는 것까지만.
