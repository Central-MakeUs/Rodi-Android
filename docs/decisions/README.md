# docs/decisions — Architecture Decision Records

구조·규약을 바꾸는 결정을 기록한다. "왜 이렇게 돼 있지?"에 답하기 위한 문서이고,
코드만 봐서는 복원할 수 없는 정보(선택지, 트레이드오프, 뺀 이유)를 남기는 게 목적이다.

## 쓰는 법

1. `TEMPLATE.md`를 복사해 `NNNN-짧은-영문-슬러그.md`로 만든다. 번호는 이어서 매긴다.
2. **`## 무효화하는 규범 항목`을 반드시 채운다.** 이 칸이 이 리포에서 문서 갱신을
   자동화하는 유일한 지점이다 — 구조를 바꾸는 변경은 반드시 ADR을 거치므로, 여기서
   걸러내면 문서가 조용히 썩는 걸 막을 수 있다.
3. 결정을 뒤집을 땐 기존 ADR을 고치지 말고 새 ADR을 쓴 뒤, 기존 것의 상태를
   `대체됨 (→ NNNN)`으로 바꾼다. 틀린 결정도 이력으로 남아야 같은 논의를 반복하지 않는다.

## 언제 쓰는가

- 모듈 경계·의존성 출처를 바꿀 때
- 공통 규약(에러 처리, 상태 관리, 테스트 엔진 등)을 정하거나 바꿀 때
- "왜 더 쉬운 방법을 안 썼지?"라는 질문이 나올 만한 선택을 할 때

단순 버그 수정이나 기능 추가는 대상이 아니다 — 커밋 메시지와 PR로 충분하다.
